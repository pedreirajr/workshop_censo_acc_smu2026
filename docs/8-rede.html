8  Leitura dos arquivos e montagem da rede

Medir acessibilidade exige saber quanto tempo se leva para ir de cada origem a cada destino, por cada modo de interesse. Esse cálculo depende de uma representação computacional da rede de transportes, montada a partir de arquivos de origens distintas. Este capítulo apresenta os quatro insumos usados na oficina, mostra como obtê-los e inspecioná-los, e constrói com eles a rede de roteamento de Anápolis.

NotaNesta seção você vai
  • baixar os dados da oficina e organizá-los nas pastas do projeto
  • inspecionar a grade de uso do solo, a rede viária, o modelo de elevação e o GTFS
  • construir a rede de roteamento com build_network()
  • conferir os erros de validação do GTFS
  • visualizar a rede efetivamente usada pelo R5

8.1 Os dados da oficina

Quatro arquivos sustentam toda a Parte 2. Nenhum deles é produzido por código, então todos são distribuídos como assets de um release do repositório da oficina, e cada nome na tabela abaixo é o link direto de download.

Arquivo Conteúdo Destino no projeto
anapolis.pbf Rede viária (OpenStreetMap) do município dados/r5/
Anapolis.tif Modelo digital de elevação (MDE), usado para custo de caminhada e bicicleta em ladeiras dados/r5/
GTFS_ANL.zip Feed GTFS do transporte público de Anápolis dados/r5/
grade_h3r9_anapolis_empregos_renda_pop_urbano_rural.gpkg Grade de hexágonos H3 (resolução 9) com número de empregos, população, renda média e classificação urbano/rural dados/geo/

Não é preciso baixar nada à mão. O bloco abaixo cria as pastas dentro do projeto do RStudio e busca cada arquivo na URL do release. Ele confere antes se o arquivo já existe, então rodá-lo de novo em outra sessão não repete o download.

ImportanteRode isto dentro do projeto do RStudio

Os caminhos são relativos à raiz do projeto. Abra o workshop_censo_acc_smu2026.Rproj antes de executar, ou o R vai criar a pasta dados/ em outro lugar.

url_base <- "https://github.com/pedreirajr/workshop_censo_acc_smu2026/releases/download/dados"

baixa_dado <- function(arquivo, destino) {
  caminho <- file.path(destino, arquivo)

  if (!file.exists(caminho)) {
    dir.create(destino, recursive = TRUE, showWarnings = FALSE)
    download.file(paste0(url_base, "/", arquivo), caminho, mode = "wb")
  }

  caminho
}

pasta_rede <- "dados/r5"
pasta_geo  <- "dados/geo"

# insumos da rede de roteamento
invisible(lapply(
  c("anapolis.pbf", "Anapolis.tif", "GTFS_ANL.zip"),
  baixa_dado,
  destino = pasta_rede
))

# grade de uso do solo
arq_grade <- baixa_dado(
  "grade_h3r9_anapolis_empregos_renda_pop_urbano_rural.gpkg",
  destino = pasta_geo
)

list.files(c(pasta_rede, pasta_geo), full.names = TRUE)

São cerca de 30 MB no total, então o primeiro download leva alguns minutos em conexão lenta. Da segunda vez em diante é instantâneo.

8.2 Grade de uso do solo (H3, resolução 9)

A grade é um conjunto de hexágonos H3 cobrindo todo o município, com número de empregos, população, renda média e uma classificação urbano ou rural por hexágono. Ela foi elaborada a partir de dados do IBGE, com os produtos tratados na Parte 1.

grade <- st_read(arq_grade, quiet = TRUE)

glimpse(sf::st_drop_geometry(grade))
  • id_hex, identificador do hexágono H3
  • Jobs, número de empregos no hexágono
  • pop_ph, população residente no hexágono
  • avg_inc_resp, renda média domiciliar per capita dos residentes
  • classe_urbano, "Urbano" ou "Rural"
table(grade$classe_urbano)

A maior parte da área do município é rural, mas concentra pouca população e quase nenhum emprego. O grosso da atividade urbana está nos cerca de 1.700 hexágonos classificados como "Urbano". É neles que o cálculo de acessibilidade vai focar, para manter o processamento leve e o resultado interpretável.

mapview(
  grade |>
    filter(classe_urbano == "Urbano"),
  zcol = "Jobs",
  layer.name = "Empregos por hexágono"
)
mapview(
  grade |>
    filter(classe_urbano == "Urbano"),
  zcol = "avg_inc_resp",
  layer.name = "Renda média (R$)"
)

8.3 Rede viária (OpenStreetMap)

O arquivo anapolis.pbf é um extrato do OpenStreetMap. O GDAL, por meio do sf, lê .pbf com o driver OSM, que expõe a rede em várias camadas.

st_layers(file.path(pasta_rede, "anapolis.pbf"))

A camada lines traz as vias (ruas, avenidas, ciclovias e outras), usada pelo r5r para caminhada, bicicleta e carro.

vias <- st_read(
  file.path(pasta_rede, "anapolis.pbf"),
  layer = "lines",
  quiet = TRUE
)

ggplot(vias) +
  geom_sf(linewidth = 0.15, color = "gray30") +
  theme_minimal() +
  labs(title = "Rede viária de Anápolis (OSM)")

8.4 Elevação (MDE)

Anapolis.tif é um modelo digital de elevação cobrindo a mesma área do extrato OSM. O r5r usa esse raster para estimar o efeito de subidas e descidas no tempo de caminhada e de bicicleta.

mde <- rast(file.path(pasta_rede, "Anapolis.tif"))
mde <- setMinMax(mde)

plot(mde, main = "Modelo digital de elevação - Anápolis (m)")
c(
  min  = global(mde, "min", na.rm = TRUE)[1, 1],
  max  = global(mde, "max", na.rm = TRUE)[1, 1],
  mean = global(mde, "mean", na.rm = TRUE)[1, 1]
)

O terreno varia de aproximadamente 686 a 1.158 metros, desnível relevante o suficiente para impactar tempos de caminhada e de bicicleta em algumas regiões do município.

8.5 Transporte público (GTFS)

GTFS_ANL.zip é o feed de transporte público. Não precisamos descompactá-lo manualmente para usar no r5r, que lê o .zip diretamente, mas vale explorar seu conteúdo antes.

gtfs_dir <- file.path(tempdir(), "gtfs_anl")
unzip(file.path(pasta_rede, "GTFS_ANL.zip"), exdir = gtfs_dir)

list.files(gtfs_dir)
calendario <- fread(file.path(gtfs_dir, "calendar.txt"))
calendario
AvisoAtenção à data de validade do feed

Este feed tem um único service_id, válido apenas em 22/07/2026 (start_date = end_date = 20260722). Isso significa que, ao rotear por transporte público com o r5r, o departure_datetime precisa cair nessa data. Qualquer outra data não terá viagens programadas. Essa é a data usada no capítulo seguinte.

paradas <- fread(file.path(gtfs_dir, "stops.txt")) |>
  st_as_sf(coords = c("stop_lon", "stop_lat"), crs = 4326)

mapview(paradas, layer.name = "Paradas de ônibus")

Com os quatro insumos conferidos, rede viária, elevação, GTFS e uso do solo, podemos construir a rede de roteamento.

8.6 Construindo a rede de transporte

O r5r::build_network() exige que todos os insumos estejam na mesma pasta, um único arquivo .pbf, opcionalmente um ou mais .zip de GTFS e opcionalmente um .tif de elevação. Ele também grava nessa pasta o arquivo network.dat, com a rede já processada em cache, e um gtfs_errors.csv.

ImportanteUma pasta só para a rede

Mantenha em dados/r5/ apenas os insumos da rede. Se a pasta estiver sincronizada com um serviço de nuvem, considere movê-la para um diretório local, porque o network.dat pode ficar com dezenas de megabytes e seria sincronizado sem necessidade.

r5r_network <- build_network(
  data_path = pasta_rede,
  elevation = "TOBLER",
  overwrite = FALSE
)

r5r_network
  • elevation = "TOBLER" faz o R5 penalizar o tempo de caminhada e de bicicleta em ladeiras, usando o Anapolis.tif que o bloco de download colocou em dados/r5/.
  • Da primeira vez, o build_network() demora, porque compila o grafo a partir do .pbf e do GTFS. Nas próximas vezes, com overwrite = FALSE (o padrão), ele reaproveita o network.dat já salvo e carrega quase instantaneamente.
  • Se algo no GTFS ou no .pbf mudar, rode com overwrite = TRUE para reconstruir do zero.

8.7 Conferindo erros do GTFS

O build_network() valida o GTFS e salva os problemas encontrados em gtfs_errors.csv. Vale sempre checar.

erros_gtfs <- get_gtfs_errors(r5r_network)
erros_gtfs

Erros de prioridade "HIGH" impedem a construção da rede, caso em que o build_network() já teria parado com um erro. Erros de prioridade mais baixa não bloqueiam, mas vale entender o que significam antes de confiar nos resultados de transporte público.

No GTFS de Anápolis usado nesta oficina aparecem cerca de 867 avisos, todos de prioridade LOW ou MEDIUM, a maioria DuplicateKeyError em stop_id (paradas cadastradas mais de uma vez) e RangeError em parent_station (referência a uma estação-mãe que não existe no stops.txt). Isso é comum em feeds GTFS reais e não impede o roteamento, mas é um bom lembrete de que “os dados vieram de um pacote” não significa “os dados estão limpos”.
