9  Cômputo dos indicadores

Com a rede construída, o caminho até um indicador de acessibilidade tem duas etapas. Primeiro se calcula quanto tempo se leva de cada origem a cada destino, o que produz uma matriz de tempos de viagem. Depois se combina essa matriz com a distribuição das oportunidades no território, o que produz o indicador. Este capítulo percorre as duas etapas para quatro modos, a pé, de bicicleta, de carro e por transporte público, e compara os resultados.

NotaNesta seção você vai
  • preparar os pontos de origem e destino a partir da grade H3
  • calcular matrizes de tempo de viagem para quatro modos
  • calcular acessibilidade cumulativa a empregos
  • calcular acessibilidade com função de decaimento (gravidade)
  • comparar os quatro modos em gráfico e em mapa

9.1 Pontos de origem e destino

Usamos o centroide de cada hexágono urbano como ponto de origem e destino. O r5r espera um data.frame ou sf com colunas id, lon e lat, em WGS84.

grade_urbana <- grade |>
  filter(classe_urbano == "Urbano") |>
  st_transform(4326)

pontos <- grade_urbana |>
  st_centroid() |>
  mutate(
    lon = st_coordinates(geom)[, 1],
    lat = st_coordinates(geom)[, 2]
  ) |>
  st_drop_geometry() |>
  transmute(id = id_hex, lon, lat)

nrow(pontos)
DicaAmostra para teste rápido

Para um teste rápido durante a aula ao vivo, use uma amostra de hexágonos em vez do conjunto completo. O cálculo fica bem mais rápido e serve para conferir que o código funciona antes de rodar tudo.

pontos_demo <- pontos |>
  slice_sample(n = 300)

Troque pontos por pontos_demo nas chamadas abaixo e depois volte para pontos para o resultado completo.

E a tabela de uso do solo, com os nomes de coluna que o accessibility espera.

uso_solo <- grade_urbana |>
  st_drop_geometry() |>
  transmute(
    id = id_hex,
    jobs = Jobs,
    population = pop_ph,
    income = avg_inc_resp
  )

head(uso_solo)

9.2 Matrizes de tempo de viagem

O transporte público só tem viagens programadas em 22/07/2026, como visto no capítulo anterior, então usamos essa data também nos outros modos, por consistência. Para caminhada, bicicleta e carro o horário não muda o resultado, porque não há tabela de horários envolvida.

data_viagem <- as.POSIXct("22-07-2026 07:00:00", format = "%d-%m-%Y %H:%M:%S")

9.2.1 A pé

ttm_pe <- travel_time_matrix(
  r5r_network = r5r_network,
  origins = pontos,
  destinations = pontos,
  mode = "WALK",
  departure_datetime = data_viagem,
  max_trip_duration = 60
)

head(ttm_pe)

9.2.4 Transporte público

Para transporte público, o modo de acesso e egresso a pé ("WALK") é combinado com "TRANSIT". Usar uma janela de tempo (time_window) maior deixa a estimativa mais robusta a variações de horário, e também mais lenta. Trinta minutos é um bom equilíbrio para uma aula.

ttm_transporte_publico <- travel_time_matrix(
  r5r_network = r5r_network,
  origins = pontos,
  destinations = pontos,
  mode = c("WALK", "TRANSIT"),
  departure_datetime = data_viagem,
  time_window = 30,
  max_walk_time = 30,
  max_trip_duration = 90
)

9.3 Acessibilidade cumulativa (oportunidades cumulativas)

Quantos empregos são alcançáveis em até 30 minutos, por hexágono, em cada modo? Usamos accessibility::cumulative_cutoff(), que espera a coluna de custo travel_time_p50, o tempo mediano de viagem dentro da janela usada.

acess_pe <- cumulative_cutoff(
  travel_matrix = ttm_pe,
  land_use_data = uso_solo,
  opportunity = "jobs",
  travel_cost = "travel_time_p50",
  cutoff = 30
)

acess_bike <- cumulative_cutoff(
  travel_matrix = ttm_bike,
  land_use_data = uso_solo,
  opportunity = "jobs",
  travel_cost = "travel_time_p50",
  cutoff = 30
)

acess_carro <- cumulative_cutoff(
  travel_matrix = ttm_carro,
  land_use_data = uso_solo,
  opportunity = "jobs",
  travel_cost = "travel_time_p50",
  cutoff = 30
)

acess_tp <- cumulative_cutoff(
  travel_matrix = ttm_transporte_publico,
  land_use_data = uso_solo,
  opportunity = "jobs",
  travel_cost = "travel_time_p50",
  cutoff = 30
)

Juntando os quatro resultados em uma única tabela, para comparar.

acess_modos <- bind_rows(
  acess_pe |>
    mutate(modo = "A pe"),
  acess_bike |>
    mutate(modo = "Bicicleta"),
  acess_carro |>
    mutate(modo = "Carro"),
  acess_tp |>
    mutate(modo = "Transporte publico")
)

ggplot(acess_modos, aes(x = modo, y = jobs, fill = modo)) +
  geom_boxplot(show.legend = FALSE) +
  labs(
    title = "Empregos alcançáveis em até 30 minutos, por modo",
    x = NULL, y = "Empregos acessíveis"
  ) +
  theme_minimal()

E em mapa, para o transporte público.

grade_urbana |>

9.4 Acessibilidade por gravidade

A abordagem de oportunidades cumulativas usa um corte rígido, em que 30 minutos “conta” e 31 minutos “não conta”. Uma alternativa é ponderar as oportunidades pelo tempo de viagem com uma função de decaimento, por exemplo uma decaída exponencial, em que oportunidades mais distantes pesam cada vez menos.

acess_grav_tp <- gravity(
  travel_matrix = ttm_transporte_publico,
  land_use_data = uso_solo,
  opportunity = "jobs",
  travel_cost = "travel_time_p50",
  decay_function = decay_exponential(decay_value = 0.1)
)

head(acess_grav_tp)

Outras funções de decaimento disponíveis no accessibility são decay_binary(), decay_linear(), decay_logistic(), decay_power() e decay_stepped(), todas documentadas em ?decay_exponential e na vinheta de funções de decaimento do pacote.

Com a acessibilidade calculada para os quatro modos, o próximo passo é olhar para quem se beneficia mais ou menos dela.
