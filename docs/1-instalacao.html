1  Instalação e ajustes iniciais

Toda a oficina roda dentro de um único projeto do RStudio, distribuído pronto em um arquivo compactado. Nele estão a estrutura de pastas, os arquivos de dados que não são baixados por código e um script de R em branco para cada capítulo. Este capítulo trata de duas tarefas apenas, obter esse pacote e instalar os pacotes de R da Parte 1. As duas devem ser feitas antes do evento, com calma e conexão estável.

NotaNesta seção você vai
  • baixar e extrair o pacote da oficina
  • abrir o projeto do RStudio e entender por que isso importa
  • reconhecer a estrutura de pastas e o script de cada capítulo
  • instalar os pacotes de R usados na Parte 1
Importante

A oficina supõe que você já tenha o R e o RStudio instalados e funcionando. Se ainda não for o caso, instale primeiro o R, a partir do CRAN, e depois o RStudio Desktop.

1.1 O pacote da oficina

Baixe o arquivo workshop_smu2026.zip, com cerca de 30 MB, e extraia em um lugar estável do seu computador, como a pasta de documentos. Evite extrair para a área de trabalho temporária ou para dentro da pasta de downloads, porque o projeto vai ser usado nos quatro blocos da oficina e precisa continuar no mesmo lugar do começo ao fim.

A extração produz uma pasta com esta estrutura.

workshop_smu2026/
├── workshop_smu2026.Rproj
├── LEIA-ME.txt
├── scripts/
│   ├── 1-instalacao_censo.R
│   ├── 2-geo.R
│   ├── 3-agregados.R
│   ├── 4-microdados.R
│   ├── 5-cnefe.R
│   ├── 6-grade.R
│   ├── 7-instalacao_acc.R
│   ├── 8-rede.R
│   ├── 9-indicadores.R
│   └── 10-equidade.R
└── dados/
    ├── censo/
    ├── geo/
    └── r5/

1.2 Abra o projeto, não os arquivos soltos

Dentro da pasta extraída há o arquivo workshop_smu2026.Rproj, e é ele que vamos abrir inicialmente. Um duplo clique nesse arquivo abre o RStudio já com o diretório de trabalho apontado para a pasta do projeto, que é o que faz os caminhos relativos dos scripts funcionarem sem ajuste algum. Quando o código pede dados/r5/anapolis.pbf, ele encontra o arquivo porque o R está posicionado na raiz do projeto.

Dica

Para confirmar que está no lugar certo, rode getwd() no console. A resposta tem de terminar em workshop_smu2026. Se terminar em outra coisa, feche o RStudio e abra novamente pelo .Rproj.

1.3 Um script por capítulo

Cada capítulo do site tem o seu arquivo correspondente em scripts/. Eles vêm todos em branco, de propósito, e serão preenchidos durante a aula, à medida que o código for apresentado. A ideia é acompanhar a explicação no site e digitar as linhas no script do capítulo, porque é digitando que a sintaxe se fixa.

As pastas de dados seguem a mesma divisão. Em dados/geo/ e dados/r5/ estão os arquivos que já vêm prontos no pacote, como a grade hexagonal de Anápolis, os estabelecimentos de saúde do CNES, a rede viária do OpenStreetMap e o GTFS do transporte público. A pasta dados/censo/ começa vazia de propósito, porque os produtos do Censo são baixados ao vivo pelos pacotes censobr e cnefetools ao longo dos capítulos 3, 4 e 5.

1.4 Instalação dos pacotes da Parte 1

O código a seguir vai para o scripts/1-instalacao_censo.R. Ele instala apenas o que estiver faltando, de modo que rodá-lo com o ambiente já pronto não custa nada.

pacotes <- c(
  "tidyverse",   # manipulação e visualização de dados
  "sf",          # dados geográficos vetoriais
  "geobr",       # malhas territoriais oficiais
  "censobr",     # produtos do Censo Demográfico
  "arrow",       # leitura de arquivos grandes em formato parquet
  "srvyr",       # estimativas com pesos amostrais
  "h3jsr",       # grade hexagonal H3
  "mapview",     # visualização interativa rápida
  "remotes"      # instalação de pacotes hospedados no GitHub
)

faltando <- pacotes[!pacotes %in% rownames(installed.packages())]

if (length(faltando) > 0) {
  install.packages(faltando, repos = "https://cloud.r-project.org")
}

O cnefetools, usado no capítulo do CNEFE, não está no CRAN e é instalado direto do GitHub.

if (!"cnefetools" %in% rownames(installed.packages())) {
  remotes::install_github("pedreirajr/cnefetools")
}
AvisoInstalação do sf

O sf depende das bibliotecas GDAL, GEOS e PROJ. No Windows e no macOS o CRAN entrega binários prontos e a instalação é direta. No Linux é preciso instalar as bibliotecas do sistema antes, o que em distribuições baseadas em Debian se faz com sudo apt install libgdal-dev libgeos-dev libproj-dev libudunits2-dev.

Por fim, carregue tudo. Se as linhas abaixo passarem sem mensagem de erro, o ambiente da Parte 1 está pronto.

library(tidyverse)
library(sf)
library(geobr)
library(censobr)
library(arrow)
library(srvyr)
library(h3jsr)
library(mapview)
library(cnefetools)

A Parte 2 exige um ambiente adicional, com o Java e os pacotes de roteamento, tratado no Capítulo 7. Vale fazer as duas instalações de uma vez, antes do evento.
